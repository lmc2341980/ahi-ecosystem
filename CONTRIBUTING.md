# Contributing to AHI Ecosystem / Hướng dẫn Đóng góp cho Hệ sinh thái AHI

---

## 🇺🇸 English Version

We love open-source contributions! To ensure a smooth collaboration process for the **AHI Ecosystem**, please follow these guidelines.

### 🐛 Reporting Bugs & Feature Requests
1. Search the **Issues** tab to check if the bug or feature request has already been reported.
2. If not, open a new Issue using our template.
3. Provide a clear description, reproduction steps, and relevant log files or screenshots.

### 🛠️ Submitting Code Changes (Pull Requests)
1. Fork the repository and create your branch from `main`.
2. Ensure your code complies with our formatting standards and passes all local tests.
3. Write clean, descriptive commit messages.

### ✒️ Mandatory CLA Signing
To protect the ecosystem's commercial viability and our dual-licensing structure, **all Pull Requests require a signed Contributor License Agreement (CLA)**.
* When you open a Pull Request, our automated **CLA Assistant Bot** will leave a comment.
* Review the terms in [CLA.md](CLA.md).
* Simply reply to the bot's comment with the exact phrase:  
  `I have read the CLA Document and I sign the CLA`
* Once signed, the bot will unblock your Pull Request for review.

## 🇻🇳 Phiên bản tiếng Việt

Chúng tôi rất hoan nghênh các đóng góp từ cộng đồng! Để đảm bảo quy trình hợp tác diễn ra mượt mà cho **AHI Ecosystem**, vui lòng tuân thủ các hướng dẫn sau.

### 🐛 Báo lỗi & Đề xuất tính năng mới
1. Tìm kiếm trong tab **Issues** để kiểm tra xem lỗi hoặc tính năng đó đã được báo cáo trước đó chưa.
2. Nếu chưa, hãy tạo một Issue mới.
3. Cung cấp mô tả rõ ràng, các bước tái hiện lỗi kèm theo file log hoặc ảnh chụp màn hình liên quan.

### 🛠️ Gửi các thay đổi về code (Pull Requests)
1. Fork kho mã nguồn này và tạo nhánh (branch) mới từ nhánh `main`.
2. Đảm bảo mã nguồn của bạn tuân thủ các tiêu chuẩn định dạng code của dự án và vượt qua các bài kiểm tra (tests) nội bộ.
3. Viết thông điệp commit (commit messages) rõ ràng, ngắn gọn nhưng đủ ý.

### ✒️ Bắt buộc ký thỏa thuận CLA
Để bảo vệ tính bền vững thương mại của hệ sinh thái và mô hình giấy phép kép, **tất cả các Pull Request đều bắt buộc phải ký Thỏa thuận cấp phép cộng tác viên (CLA)**.
* Khi bạn tạo một Pull Request, con **Bot CLA Assistant** tự động của chúng tôi sẽ để lại một bình luận.
* Đọc kỹ các điều khoản pháp lý tại file [CLA.md](CLA.md).
* Phản hồi lại bình luận của bot bằng cú pháp chính xác sau:  
  `I have read the CLA Document and I sign the CLA`
* Ngay sau khi ký, bot sẽ mở khóa Pull Request để đội ngũ kỹ sư tiến hành kiểm duyệt code.
